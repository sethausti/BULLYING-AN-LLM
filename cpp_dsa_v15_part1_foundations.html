1. int

The int type stores signed integers, typically 32 bits on modern systems. Range is usually -2,147,483,648 to 2,147,483,647. It is the most common integer type due to its balance of range and performance. Use int for loop counters and general counting.

int x = 10;
int y = -5;
int sum = x + y; // 5
cout << sizeof(int); // usually 4 bytes

2. long long

long long is a 64-bit signed integer type guaranteeing at least 64 bits. Use it when int would overflow, such as for large sums or products. Range is approx -9e18 to 9e18. Essential for competitive programming problems with constraints up to 1e18.

long long big = 10000000000LL;
long long result = big * big; // no overflow
cout << sizeof(long long); // 8 bytes

3. float

float is a 32-bit single-precision floating point type. It provides about 6-7 decimal digits of precision. Use float when memory is tight and precision is not critical. For most scientific work, double is preferred due to higher precision.

float pi = 3.14159f;
float r = 2.5f;
float area = pi * r * r;
printf("%.6f\n", area); // 19.634937

4. double

double is a 64-bit double-precision floating point type with 15-16 decimal digits of precision. It is the default choice for real numbers in C++. Arithmetic with double is often as fast as float on modern CPUs. Always use double unless memory constraints force float.

double e = 2.718281828459045;
double x = 1.0 / 3.0;
cout << fixed << setprecision(15) << x; // 0.333333333333333

5. char

char stores a single character or small integer, typically 1 byte. It can be signed or unsigned depending on compiler. ASCII values range 0-127, extended 0-255. Use char for text processing and as the fundamental unit of std::string.

char c = 'A';
char digit = '7';
int ascii = c; // 65
c = c + 1; // 'B'
cout << (char)('a' - 32); // 'A'

6. bool

bool stores truth values: true or false. Internally usually 1 byte, though only 1 bit is needed. Any non-zero value converts to true, zero to false. Use bool for flags and conditional logic. Comparisons return bool automatically.

bool flag = true;
bool isEqual = (5 > 3); // true
if (flag) cout << "Yes";
int x = 0;
bool b = x; // false

7. void

void means "no type". It is used for functions that return nothing. void* is a generic pointer that can point to any type but cannot be dereferenced directly. You cannot declare a variable of type void. It indicates absence of value.

void printHello() {
    cout << "Hello";
    return; // optional
}
void* ptr;
int x = 5;
ptr = &x; // OK

8. auto

auto tells the compiler to deduce the type from the initializer. It reduces verbosity and prevents implicit conversions. Use auto for iterators, lambdas, and complex types. Since C++14, auto can deduce return types. Avoid auto when type clarity is important.

auto x = 5; // int
auto y = 3.14; // double
vector<int> v;
auto it = v.begin(); // vector<int>::iterator
auto lambda = [](int a){ return a*a; };

9. const

const declares a variable whose value cannot change after initialization. const improves code safety and enables compiler optimizations. const can apply to pointers in multiple ways. Use const for values that should remain immutable throughout program execution.

const int MAX = 100;
const double PI = 3.14159;
// MAX = 200; // error
const int* p1; // pointer to const int
int* const p2 = &x; // const pointer

10. static

static has multiple meanings: inside functions, it preserves value between calls. At file scope, it gives internal linkage. In classes, static members are shared by all instances. Static variables are zero-initialized and stored in data segment.

void counter() {
    static int count = 0; // init once
    count++;
    cout << count;
}
static int fileVar = 5; // internal linkage

11. Functions Basics

Functions encapsulate reusable code blocks with a name, parameters, and return type. They enable modularity, abstraction, and code reuse. A function must be declared before use or defined. The main function is the program entry point. Functions can be overloaded with different parameter lists.

int add(int a, int b) {
    return a + b;
}
int main() {
    int result = add(3, 4); // 7
    return 0;
}

12. Pass by Value

Pass by value creates a copy of the argument. The function cannot modify the original variable. This is safe but expensive for large objects. Primitives are typically passed by value. Changes inside the function do not affect the caller.

void increment(int x) {
    x++; // only local copy changes
}
int main() {
    int num = 5;
    increment(num);
    cout << num; // still 5
}

13. Pass by Reference

Pass by reference passes an alias to the original variable using &. Modifications affect the caller. No copy is made, so it is efficient for large objects. Use const reference to avoid copying while preventing modification. References must be initialized.

void increment(int& x) {
    x++; // modifies original
}
int main() {
    int num = 5;
    increment(num);
    cout << num; // 6
}

14. Pointers Intro

A pointer stores the memory address of another variable. Declared with *. The & operator gets the address of a variable. Pointers enable dynamic memory, arrays, and efficient parameter passing. Uninitialized pointers contain garbage and are dangerous.

int x = 10;
int* ptr = &x; // ptr stores address of x
cout << ptr; // 0x... address
cout << *ptr; // 10, dereference

15. Dereference

The * operator dereferences a pointer to access the value it points to. Dereferencing a null or invalid pointer causes undefined behavior. You can modify the pointed-to value through dereference. * has lower precedence than ++ so use (*ptr)++ to increment value.

int x = 5;
int* p = &x;
*p = 20; // x is now 20
cout << x; // 20
(*p)++; // x becomes 21

16. Null Pointer

A null pointer points to nothing. Use nullptr in C++11 instead of NULL or 0. Dereferencing nullptr crashes the program. Always check pointers before dereferencing. nullptr has type nullptr_t and converts to any pointer type safely.

int* p = nullptr;
if (p != nullptr) {
    cout << *p; // safe check
}
p = new int(5);
delete p;
p = nullptr; // avoid dangling

17. Pointer Arithmetic

Adding an integer to a pointer moves it by n elements, not bytes. ptr + 1 advances by sizeof(*ptr) bytes. Only valid within same array or one past end. Pointer subtraction gives element distance. Cannot add two pointers together.

int arr[5] = {10,20,30,40,50};
int* p = arr; // points to arr[0]
p++; // now points to arr[1]
cout << *p; // 20
int diff = p - arr; // 1

18. References

References are aliases for existing variables, declared with &. Must be initialized and cannot be reassigned to another variable. Safer than pointers as they cannot be null. Used heavily for parameter passing and operator overloading. Think of references as constant pointers with automatic dereference.

int x = 10;
int& ref = x; // ref is alias for x
ref = 20; // x is now 20
// int& r; // error, must init
// ref = &y; // error, cannot rebind

19. Function Overload

Function overloading allows multiple functions with same name but different parameters. The compiler selects based on argument types and count. Return type alone cannot differentiate overloads. Overloading improves API readability. Ambiguous calls cause compile errors.

int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; }
int add(int a, int b, int c) { return a + b + c; }
add(2, 3); // calls int version
add(2.5, 3.5); // calls double version

20. Default Args

Default arguments provide values for parameters not supplied by caller. Specified in function declaration only. Default args must appear at end of parameter list. They reduce overloads needed. Be careful with ambiguity when overloading functions with default args.

void print(int x, int y = 0, int z = 0) {
    cout << x << y << z;
}
print(1); // 100
print(1, 2); // 120
print(1, 2, 3); // 123

21. struct Basics

struct groups related variables under one type. Members are public by default. Use struct to create custom data types representing entities. Each instance has its own copy of members. structs can contain methods and constructors. Memory layout matches declaration order.

struct Point {
    int x;
    int y;
};
Point p1 = {3, 4};
p1.x = 5;
cout << p1.y; // 4

22. struct Methods

structs can have member functions that operate on their data. Methods have access to all members. The 'this' pointer refers to the calling instance. Use methods to enforce invariants and encapsulate behavior. Constructors initialize objects automatically.

struct Rectangle {
    int w, h;
    Rectangle(int w, int h) : w(w), h(h) {}
    int area() { return w * h; }
};
Rectangle r(5, 3);
cout << r.area(); // 15

23. enum

enum defines a set of named integer constants. Improves code readability over magic numbers. Unscoped enums pollute namespace and implicitly convert to int. By default, first enumerator is 0, each next increments by 1. You can assign specific values.

enum Color { RED, GREEN, BLUE }; // 0,1,2
enum Status { OK = 200, ERROR = 500 };
Color c = RED;
int x = GREEN; // implicit convert, x=1

24. enum class

enum class creates scoped enumerations that do not implicitly convert to int. Prevents namespace pollution and type errors. Must qualify with EnumName::. Introduced in C++11. Always prefer enum class over plain enum for type safety.

enum class Direction { NORTH, SOUTH, EAST, WEST };
Direction d = Direction::NORTH;
// int x = d; // error, no implicit convert
int x = static_cast<int>(d); // explicit OK

25. typedef

typedef creates aliases for existing types. Simplifies complex type names like function pointers. using is the modern alternative since C++11. Type aliases do not create new types, just alternative names. Helpful for portability and readability of code.

typedef long long ll;
typedef unsigned int uint;
using ll = long long; // C++11 style
ll big = 10000000000LL;
uint x = 5;

26. C-Array Basics

C-style arrays store fixed-size sequences of elements contiguously in memory. Size must be known at compile time. Array name decays to pointer to first element. Indexing starts at 0. No bounds checking occurs, so accessing out of range is undefined behavior.

int arr[5]; // uninitialized
arr[0] = 10;
arr[4] = 50;
cout << arr[2]; // garbage value
int* p = arr; // decays to pointer

27. Array Init

Arrays can be initialized with brace lists. Missing elements are zero-initialized. int arr[5] = {1,2}; sets arr[0]=1, arr[1]=2, rest 0. int arr[] = {1,2,3}; deduces size as 3. String literals initialize char arrays with null terminator.

int a[5] = {1, 2, 3, 4, 5};
int b[5] = {1, 2}; // {1,2,0,0,0}
int c[] = {1, 2, 3}; // size 3
char str[] = "Hi"; // {'H','i','\0'}

28. 2D Arrays

2D arrays are arrays of arrays, stored in row-major order. Declared as type name[rows][cols]. Elements accessed with arr[i][j]. Memory is contiguous: arr[i][j] is at address arr + i*cols + j. All rows must have same number of columns.

int mat[3][4]; // 3 rows, 4 cols
mat[0][0] = 1;
mat[2][3] = 12;
int arr[2][3] = {{1,2,3}, {4,5,6}};

29. Array Decay

When passed to functions, arrays decay to pointers, losing size information. sizeof inside function gives pointer size, not array size. Pass size explicitly or use std::array/vector. This is why C arrays are error-prone compared to STL containers.

void func(int arr[]) { // actually int* arr
    cout << sizeof(arr); // 8, pointer size
}
int a[10];
cout << sizeof(a); // 40
func(a); // decays

30. std::array

std::array is a fixed-size container that wraps C-arrays with STL interface. Provides size(), bounds-checked at(), and iterators. No performance overhead versus C-array. Size is part of type. Preferred over C-arrays for safety and convenience.

#include <array>
array<int, 5> arr = {1,2,3,4,5};
cout << arr.size(); // 5
arr[0] = 10;
arr.at(4) = 50; // bounds checked
// arr.at(5); // throws exception

31. vector Basics

vector is a dynamic array that grows automatically. Stored contiguously like arrays, enabling O(1) random access. Manages memory automatically, unlike C-arrays. Most frequently used STL container. Growth strategy typically doubles capacity to achieve amortized O(1) push_back.

#include <vector>
vector<int> v; // empty
vector<int> v2(5); // 5 zeros
vector<int> v3(5, 10); // 5 tens
vector<int> v4 = {1,2,3};

32. push_back

push_back appends element to end of vector. Amortized O(1) time complexity. If capacity exceeded, vector reallocates with larger capacity and copies elements. Use reserve() to avoid reallocations if size known. emplace_back constructs in-place, slightly faster.

vector<int> v;
v.push_back(10);
v.push_back(20);
v.push_back(30); // v = {10,20,30}
cout << v.capacity(); // >= 3

33. vector Size

size() returns number of elements. capacity() returns allocated space. size <= capacity always. reserve(n) ensures capacity at least n. resize(n) changes size and constructs/destroys elements. clear() removes all elements but keeps capacity.

vector<int> v = {1,2,3};
cout << v.size(); // 3
v.reserve(100); // capacity >= 100
v.resize(5); // v = {1,2,3,0,0}
v.clear(); // size 0, capacity unchanged

34. vector Iterate

Vectors support index-based and iterator-based iteration. Range-based for loop is modern and safe. Use const auto& to avoid copies. begin() and end() return iterators. Reverse iteration uses rbegin() and rend(). Prefer range-for for readability.

vector<int> v = {10,20,30};
for(int i = 0; i < v.size(); i++) cout << v[i];
for(auto it = v.begin(); it != v.end(); ++it) cout << *it;
for(int x : v) cout << x;
for(const auto& x : v) cout << x;

35. 2D vector

2D vectors are vectors of vectors: vector<vector<int>>. Each row can have different size, unlike 2D arrays. Initialization requires careful syntax. Memory is not contiguous across rows. Access with v[i][j]. Reserve space for performance if dimensions known.

vector<vector<int>> mat(3, vector<int>(4, 0)); // 3x4 zeros
mat[0][0] = 1;
mat[1][2] = 5;
vector<vector<int>> jagged = {{1,2}, {3,4,5}};

36. string Basics

std::string stores and manipulates text. Dynamic length, unlike char arrays. Provides rich member functions. Supports concatenation with +. Stored contiguously and null-terminated since C++11. Automatically manages memory. Size does not include null terminator.

#include <string>
string s1 = "Hello";
string s2("World");
string s3(5, 'a'); // "aaaaa"
cout << s1.size(); // 5
s1[0] = 'h'; // "hello"

37. string Concat

string supports + for concatenation, creating new string. += modifies in place, more efficient. append() also concatenates. push_back adds single char. Concatenating string literal with + requires at least one operand to be string object to avoid pointer arithmetic.

string a = "Hello";
string b = "World";
string c = a + " " + b; // "Hello World"
a += "!"; // "Hello!"
a.append(b);
a.push_back('?');

38. string substr

substr(pos, len) returns substring starting at pos with length len. If len omitted, goes to end. If pos >= size, throws out_of_range. Complexity is O(len) as it copies characters. Use string_view in C++17 to avoid copies.

string s = "HelloWorld";
string sub = s.substr(5); // "World"
string sub2 = s.substr(1, 4); // "ello"
// s.substr(20); // exception
cout << sub;

39. string find

find() searches for substring or char, returns position or string::npos if not found. Variants: rfind searches backward, find_first_of finds any char in set. All run in O(n*m) worst case. Compare return value against npos to check success.

string s = "Hello World";
size_t pos = s.find("World"); // 6
if(pos != string::npos) cout << "Found";
size_t pos2 = s.find('o'); // 4
size_t pos3 = s.rfind('o'); // 7

40. getline

getline reads entire line including spaces until newline. cin >> stops at whitespace. Syntax: getline(cin, str). Returns cin so can be used in conditions. Third parameter specifies delimiter. Clears newline from buffer, unlike cin >>.

string line;
getline(cin, line); // reads "Hello World"
cout << line;
string data;
getline(cin, data, ','); // read until comma

41. Stack Concept

Stack is LIFO: Last In First Out. Only top element accessible. Operations: push adds to top, pop removes top, top/peep views top. All O(1). Used for function calls, undo, expression evaluation, DFS. Think of stack of plates.

// Conceptual LIFO operations
// push(10) -> [10]
// push(20) -> [10,20]
// pop() -> [10], returns 20
// top() -> 10

42. std::stack

std::stack is container adapter, default underlying container is deque. Provides push, pop, top, empty, size. No iterators, as stack is not meant for traversal. pop() returns void, call top() before pop to get value. Thread-safe alternatives exist.

#include <stack>
stack<int> s;
s.push(10);
s.push(20);
cout << s.top(); // 20
s.pop();
cout << s.size(); // 1
cout << s.empty(); // false

43. Array Stack

Implement stack using array and top index. Push increments top, pop decrements. Check overflow on push, underflow on pop. Fixed capacity is limitation. Array implementation is cache-friendly. Time complexity O(1) for all operations if no resize.

int st[100], top = -1;
void push(int x) { st[++top] = x; }
void pop() { if(top >= 0) top--; }
int peek() { return st[top]; }
bool empty() { return top == -1; }

44. Queue Concept

Queue is FIFO: First In First Out. Elements added at rear, removed from front. Operations: enqueue/push, dequeue/pop, front, back. All O(1). Used for BFS, scheduling, buffers, printer spool. Think of line at ticket counter.

// Conceptual FIFO
// enqueue(10) -> [10]
// enqueue(20) -> [10,20]
// dequeue() -> [20], returns 10
// front() -> 20

45. std::queue

std::queue is container adapter using deque by default. Provides push, pop, front, back, empty, size. No random access or iterators. pop() removes front element. front() accesses first element, back() accesses last. Perfect for BFS implementation.

#include <queue>
queue<int> q;
q.push(10);
q.push(20);
cout << q.front(); // 10
cout << q.back(); // 20
q.pop(); // removes 10

46. Array Queue

Simple array queue uses front and rear indices. Problem: dequeue wastes space at beginning. After many operations, rear reaches end while front moves forward. Solution is circular queue. Basic version works but memory inefficient for long-running programs.

int q[100], front = 0, rear = 0;
void enqueue(int x) { q[rear++] = x; }
void dequeue() { if(front < rear) front++; }
int peek() { return q[front]; }
bool empty() { return front == rear; }

47. Circular Queue

Circular queue reuses space by wrapping rear to 0 when end reached. Uses modulo arithmetic: (rear+1)%size. Distinguishes full vs empty using size counter or leaving one slot empty. Fixes array queue space waste. All operations O(1).

int cq[100], front = 0, rear = 0, size = 0, cap = 100;
void enqueue(int x) {
    if(size < cap) {
        cq[rear] = x;
        rear = (rear + 1) % cap;
        size++;
    }
}

48. Deque

Deque: double-ended queue. Allows insertion/deletion at both ends in O(1) amortized. Combines stack and queue functionality. Implemented as array of arrays, so not fully contiguous. Random access O(1). More memory overhead than vector but more flexible.

// Concept: push/pop at both ends
// push_front(10) -> [10]
// push_back(20) -> [10,20]
// pop_front() -> [20]
// pop_back() -> []

49. std::deque

std::deque provides push_front, push_back, pop_front, pop_back. Also supports random access with []. Grows efficiently at both ends unlike vector. Used as default for stack and queue adapters. Iterators invalidated less frequently than vector during insertions.

#include <deque>
deque<int> dq;
dq.push_back(10);
dq.push_front(5); // [5,10]
dq.pop_back(); // [5]
cout << dq[0]; // 5
dq.push_back(20); // [5,20]

50. Practice: Valid Parens

Check if string of parentheses is valid: every open has matching close in correct order. Use stack: push opens, pop on closes if matches top. If mismatch or stack not empty at end, invalid. Classic stack application. Time O(n), space O(n).

bool isValid(string s) {
    stack<char> st;
    for(char c : s) {
        if(c=='('||c=='{'||c=='[') st.push(c);
        else {
            if(st.empty()) return false;
            if(c==')'&&st.top()!='(') return false;
            if(c=='}'&&st.top()!='{') return false;
            if(c==']'&&st.top()!='[') return false;
            st.pop();
        }
    }
    return st.empty();
}
Reveal Answer

The stack tracks expected closing brackets. We push opening brackets and verify each closing bracket matches the top of stack. If stack empty when we need to pop, or types mismatch, return false. Finally check if stack empty for valid result.

51. LL Node

Linked list node contains data and pointer to next node. Unlike arrays, elements not contiguous. Dynamic size, efficient insertion/deletion at head O(1). No random access, O(n) to reach element. Extra memory for pointers. Define struct with data and Node* next.

struct Node {
    int data;
    Node* next;
    Node(int val) : data(val), next(nullptr) {}
};
Node* head = new Node(10);
head->next = new Node(20);

52. LL Insert Head

Insert at head is O(1): create new node, point its next to current head, update head to new node. No traversal needed. This is why linked lists excel at stack-like operations. Always check for memory allocation success in production code.

void insertHead(Node*& head, int val) {
    Node* newNode = new Node(val);
    newNode->next = head;
    head = newNode;
}
insertHead(head, 5); // new head is 5

53. LL Insert Tail

Insert at tail requires traversal to end, O(n), unless tail pointer maintained. Edge case: empty list where head is nullptr. Link last node's next to new node. If maintaining tail pointer, insertion becomes O(1). Common interview question.

void insertTail(Node*& head, int val) {
    Node* newNode = new Node(val);
    if(!head) { head = newNode; return; }
    Node* temp = head;
    while(temp->next) temp = temp->next;
    temp->next = newNode;
}

54. LL Delete

Delete by value: find node, update previous node's next to skip deleted node, delete node. O(n) to find. Edge cases: delete head, delete non-existent value, delete from empty list. Must update head if deleting first node. Memory leak if not deleted.

void deleteVal(Node*& head, int val) {
    if(!head) return;
    if(head->data == val) {
        Node* temp = head;
        head = head->next;
        delete temp;
        return;
    }
    Node* curr = head;
    while(curr->next && curr->next->data != val)
        curr = curr->next;
    if(curr->next) {
        Node* temp = curr->next;
        curr->next = temp->next;
        delete temp;
    }
}

55. LL Traverse

Traversal visits each node once, O(n). Use temporary pointer, not head, to avoid losing list. Stop when pointer is nullptr. Common pattern for printing, searching, counting. While loop is standard. For loop also works with pointer iteration.

void printList(Node* head) {
    Node* curr = head;
    while(curr) {
        cout << curr->data << " ";
        curr = curr->next;
    }
}
// 10 -> 20 -> 30 -> null

56. LL Search

Search sequentially through list, O(n) time. Return true if found, false otherwise. No random access means cannot use binary search even if sorted. Can return pointer to node or position. Simpler than array search due to no bounds checking.

bool search(Node* head, int key) {
    Node* curr = head;
    while(curr) {
        if(curr->data == key) return true;
        curr = curr->next;
    }
    return false;
}

57. Doubly LL

Doubly linked list nodes have next and prev pointers. Enables backward traversal and O(1) deletion if node pointer given. Uses more memory. Insert/delete require updating two pointers. Head and tail often maintained. Useful for LRU cache implementation.

struct DNode {
    int data;
    DNode* next;
    DNode* prev;
    DNode(int val) : data(val), next(nullptr), prev(nullptr) {}
};

58. DLL Insert

DLL insertion must update both next and prev pointers. At head: new node's next is old head, old head's prev is new node. At tail: symmetric. In middle: update four pointers total. More complex but enables O(1) deletion with node pointer.

void insertFront(DNode*& head, int val) {
    DNode* newNode = new DNode(val);
    newNode->next = head;
    if(head) head->prev = newNode;
    head = newNode;
}

59. Circular LL

Circular linked list: last node points to head instead of nullptr. No end to list, traversal must use do-while or check for head revisit. Useful for round-robin scheduling. Can be singly or doubly circular. Insert/delete logic differs slightly.

// Last node->next = head
void insertCircular(Node*& head, int val) {
    Node* newNode = new Node(val);
    if(!head) { 
        head = newNode; 
        newNode->next = head; 
        return; 
    }
    Node* temp = head;
    while(temp->next != head) temp = temp->next;
    temp->next = newNode;
    newNode->next = head;
}

60. Practice: Reverse LL

Reverse linked list iteratively using three pointers: prev, curr, next. Traverse list, reverse each node's next pointer to point to prev. At end, prev is new head. Time O(n), space O(1). Classic interview problem testing pointer manipulation.

Node* reverse(Node* head) {
    Node* prev = nullptr;
    Node* curr = head;
    while(curr) {
        Node* next = curr->next;
        curr->next = prev;
        prev = curr;
        curr = next;
    }
    return prev; // new head
}
Reveal Answer

We maintain three pointers and iterate through the list. For each node, we save next, reverse current's next to prev, then advance prev and curr. When curr becomes null, prev points to the last node which is the new head. Draw diagrams to visualize pointer changes.

61. Tree Concept

Tree is hierarchical data structure with nodes connected by edges. Root is top node, leaves have no children. Binary tree: each node at most 2 children. Height: longest path root to leaf. Depth: distance from root. Trees enable fast search, insert, delete.

// Root -> children
// Parent-child relationship
// No cycles
// N nodes have N-1 edges

62. Binary Tree Node

Binary tree node has data, left pointer, right pointer. Leaf nodes have both pointers null. struct definition similar to linked list but two pointers. Recursive structure: left and right subtrees are also binary trees. Foundation for BST, heaps, expression trees.

struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};
TreeNode* root = new TreeNode(1);
root->left = new TreeNode(2);
root->right = new TreeNode(3);

63. BT Inorder

Inorder traversal: left, root, right. For BST, gives sorted order. Recursive: traverse left, process root, traverse right. Iterative uses stack. Time O(n), space O(h) where h is height. Call stack depth equals tree height in recursion.

void inorder(TreeNode* root) {
    if(!root) return;
    inorder(root->left);
    cout << root->val << " ";
    inorder(root->right);
}
// For BST: prints sorted

64. BT Preorder

Preorder traversal: root, left, right. Useful for copying tree, prefix expressions. Root processed before subtrees. Iterative uses stack pushing right then left. First node visited is always root. Good for creating tree copy with same structure.

void preorder(TreeNode* root) {
    if(!root) return;
    cout << root->val << " ";
    preorder(root->left);
    preorder(root->right);
}

65. BT Postorder

Postorder traversal: left, right, root. Used for deleting tree, postfix expressions. Root processed last. Bottom-up processing useful for calculating directory sizes. Harder iterative version uses two stacks or modified preorder. Children processed before parent.

void postorder(TreeNode* root) {
    if(!root) return;
    postorder(root->left);
    postorder(root->right);
    cout << root->val << " ";
}

66. BT Level Order

Level order traverses level by level using queue: BFS. Visit root, enqueue children, dequeue and repeat. Prints nodes left to right at each level. Time O(n), space O(w) where w is max width. Used in finding min depth, level averages.

void levelOrder(TreeNode* root) {
    if(!root) return;
    queue<TreeNode*> q;
    q.push(root);
    while(!q.empty()) {
        TreeNode* curr = q.front(); q.pop();
        cout << curr->val << " ";
        if(curr->left) q.push(curr->left);
        if(curr->right) q.push(curr->right);
    }
}

67. BT Height

Height of tree is max depth of any leaf. Empty tree height -1 or 0 by definition. Leaf height 0. Recursive: 1 + max(left height, right height). Important for balance analysis. Skewed tree height O(n), balanced tree height O(log n).

int height(TreeNode* root) {
    if(!root) return -1; // or 0
    int lh = height(root->left);
    int rh = height(root->right);
    return 1 + max(lh, rh);
}

68. BST Concept

Binary Search Tree: left subtree values < node value < right subtree values. Enables O(log n) average search, insert, delete if balanced. Inorder traversal gives sorted sequence. No duplicates typically. Worst case O(n) if skewed like linked list.

// BST Property
//     8
//    / \
//   3   10
//  / \    \
// 1   6    14
// All left < root < all right

69. BST Insert

Insert recursively: if empty, create node. If val < root, go left, else go right. Maintains BST property. Iterative version uses pointer to pointer or tracks parent. Time O(h), h is height. Unbalanced insertion order creates skewed tree.

TreeNode* insert(TreeNode* root, int val) {
    if(!root) return new TreeNode(val);
    if(val < root->val) 
        root->left = insert(root->left, val);
    else 
        root->right = insert(root->right, val);
    return root;
}

70. BST Search

Search recursively or iteratively. Compare with root, go left if smaller, right if larger. Return node if found, nullptr if not. Time O(h). Iterative saves stack space. BST enables binary search on tree structure. Faster than linear search.

bool search(TreeNode* root, int val) {
    if(!root) return false;
    if(root->val == val) return true;
    if(val < root->val) return search(root->left, val);
    return search(root->right, val);
}
// Iterative version also possible

71. BST Delete

Delete has 3 cases: leaf node - just delete. One child - replace with child. Two children - replace with inorder successor(min in right) or predecessor, then delete successor. Maintain BST property. Most complex BST operation. Time O(h).

TreeNode* deleteNode(TreeNode* root, int key) {
    if(!root) return root;
    if(key < root->val) root->left = deleteNode(root->left, key);
    else if(key > root->val) root->right = deleteNode(root->right, key);
    else {
        if(!root->left) { TreeNode* t = root->right; delete root; return t; }
        else if(!root->right) { TreeNode* t = root->left; delete root; return t; }
        TreeNode* t = minNode(root->right);
        root->val = t->val;
        root->right = deleteNode(root->right, t->val);
    }
    return root;
}

72. BST Min/Max

Minimum value is leftmost node, maximum is rightmost node. Traverse left until null for min, right until null for max. Time O(h). Used in deletion and validation. In balanced BST, O(log n). Does not require full traversal unlike min in array.

TreeNode* findMin(TreeNode* root) {
    while(root && root->left) root = root->left;
    return root;
}
TreeNode* findMax(TreeNode* root) {
    while(root && root->right) root = root->right;
    return root;
}

73. Balanced Trees

Balanced tree has height O(log n) ensuring O(log n) operations. AVL and Red-Black trees maintain balance via rotations. Unbalanced BST degrades to O(n) linked list. Balance factor = left height - right height. Self-balancing trees auto-rebalance on insert/delete.

// Balanced: height ~ log n
//    4
//   / \
//  2   6
// Skewed: height ~ n
// 1
//  \
//   2
//    \
//     3

74. AVL Intro

AVL tree is self-balancing BST where balance factor of every node is -1, 0, or 1. Rotations restore balance after insert/delete: LL, RR, LR, RL. Height guaranteed O(log n). More rigidly balanced than Red-Black, so lookups faster but inserts slower.

// AVL Rotations concept
// LL: right rotate
// RR: left rotate  
// LR: left then right
// RL: right then left
// Balance factor = height(left) - height(right)

75. Practice: LCA

Lowest Common Ancestor in BST: for nodes p and q, if both < root go left, if both > root go right, else root is LCA. Uses BST property. Time O(h). In general binary tree, requires different approach. LCA is deepest node that has both as descendants.

TreeNode* LCA(TreeNode* root, TreeNode* p, TreeNode* q) {
    if(!root) return nullptr;
    if(p->val < root->val && q->val < root->val)
        return LCA(root->left, p, q);
    if(p->val > root->val && q->val > root->val)
        return LCA(root->right, p, q);
    return root;
}
Reveal Answer

We use BST property: if both nodes are smaller than root, LCA is in left subtree. If both larger, LCA in right. Otherwise, root is the split point and thus LCA. This works because BST left < root < right invariant holds for all nodes.

76. Heap Concept

Heap is complete binary tree satisfying heap property: parent <= children for min-heap, parent >= children for max-heap. Root is min or max element. Not sorted. Used for priority queues. Implemented as array for cache efficiency. Height is O(log n).

// Min Heap example
//       1
//      / \
//     3   5
//    / \ / \
//   4  6 7  8
// Array: [1,3,5,4,6,7,8]

77. Min Heap

In min-heap, root is minimum element. Each parent <= children. Extract-min removes root in O(log n). Insert in O(log n) by percolate up. Get min in O(1). Used in Dijkstra, Huffman coding. Array representation: children of i are 2i+1, 2i+2.

// Min heap property: arr[i] <= arr[2i+1] && arr[i] <= arr[2i+2]
// getMin(): return arr[0]
// parent(i): (i-1)/2

78. Max Heap

Max-heap has root as maximum element. Parent >= children. Extract-max and insert both O(log n). Used in heap-sort. priority_queue default is max-heap. Convert min to max by negating values or custom comparator. Array indexing same as min-heap.

// Max heap property: arr[i] >= arr[2i+1] && arr[i] >= arr[2i+2]
// Used for heap sort: repeatedly extract max

79. priority_queue

std::priority_queue is container adapter implementing max-heap by default. push, pop, top operations. pop removes highest priority element. No iterators. Underlying container is vector. Provide custom comparator for min-heap or custom objects. Part of <queue> header.

#include <queue>
priority_queue<int> maxHeap; // max-heap
priority_queue<int, vector<int>, greater<int>> minHeap; // min-heap
maxHeap.push(3);
maxHeap.push(1);
maxHeap.push(5);
cout << maxHeap.top(); // 5
maxHeap.pop();

80. Custom Comparator

priority_queue accepts comparator to define priority. For min-heap use greater<T>. For custom objects, overload operator< or provide functor/lambda. Comparator returns true if first arg has lower priority than second. Careful with comparator logic: inverted from sort.

struct Compare {
    bool operator()(int a, int b) { return a > b; } // min-heap
};
priority_queue<int, vector<int>, Compare> pq;
auto cmp = [](int a, int b) { return a > b; };
priority_queue<int, vector<int>, decltype(cmp)> pq2(cmp);

81. Heapify

Heapify maintains heap property at node i assuming subtrees are heaps. Compare node with children, swap with smaller/larger child, recurse. Time O(log n). Build-heap from array calls heapify on non-leaf nodes bottom-up, total O(n) time despite O(n log n) appearance.

void heapify(vector<int>& arr, int n, int i) {
    int largest = i;
    int l = 2*i + 1, r = 2*i + 2;
    if(l < n && arr[l] > arr[largest]) largest = l;
    if(r < n && arr[r] > arr[largest]) largest = r;
    if(largest != i) {
        swap(arr[i], arr[largest]);
        heapify(arr, n, largest);
    }
}

82. Heap Insert

Insert at end of array, then percolate up: compare with parent, swap if violates heap property, repeat until root or property satisfied. Time O(log n) worst case. Increases size by 1. Maintains complete tree property by inserting at next available position.

void insertHeap(vector<int>& heap, int val) {
    heap.push_back(val);
    int i = heap.size() - 1;
    while(i > 0 && heap[(i-1)/2] < heap[i]) {
        swap(heap[i], heap[(i-1)/2]);
        i = (i-1)/2;
    }
}

83. Heap Extract

Extract root: save root value, move last element to root, decrease size, heapify root down. Time O(log n). This is how heap-sort works: repeatedly extract max/min. After extraction, heap property restored by heapify. Empty heap extraction is error.

int extractMax(vector<int>& heap) {
    if(heap.empty()) return -1;
    int root = heap[0];
    heap[0] = heap.back();
    heap.pop_back();
    heapify(heap, heap.size(), 0);
    return root;
}

84. Practice: Kth Largest

Find kth largest using min-heap of size k. Push elements, if size > k pop smallest. Top is kth largest. Time O(n log k). Alternative: quickselect O(n) average. Heap method works for streaming data. For kth smallest, use max-heap.

int findKthLargest(vector<int>& nums, int k) {
    priority_queue<int, vector<int>, greater<int>> pq;
    for(int num : nums) {
        pq.push(num);
        if(pq.size() > k) pq.pop();
    }
    return pq.top();
}
Reveal Answer

Maintain a min-heap of size k containing the k largest elements seen so far. When heap exceeds size k, pop the smallest. After processing all elements, the top of min-heap is the kth largest. This avoids sorting entire array, efficient for large n and small k.

85. Practice: Median Stream

Maintain median of streaming data using two heaps: max-heap for lower half, min-heap for upper half. Balance sizes. Median is top of larger heap or average of tops if equal size. Insert O(log n), find median O(1). Classic heap application.

priority_queue<int> maxHeap; // lower half
priority_queue<int, vector<int>, greater<int>> minHeap; // upper half
void addNum(int num) {
    maxHeap.push(num);
    minHeap.push(maxHeap.top()); maxHeap.pop();
    if(minHeap.size() > maxHeap.size()) {
        maxHeap.push(minHeap.top()); minHeap.pop();
    }
}
double findMedian() {
    return maxHeap.size() > minHeap.size() ? maxHeap.top() : 
           (maxHeap.top() + minHeap.top()) / 2.0;
}
Reveal Answer

Keep max-heap for smaller half and min-heap for larger half. Ensure size difference <= 1. Add new number to max-heap, move max to min-heap, rebalance if needed. Median is max-heap top if odd count, else average of both tops. This keeps halves balanced.

87. Graph Terms

88. Adj Matrix

Adjacency matrix is V×V boolean matrix where mat[i][j] = 1 if edge i->j exists. Space O(V²), check edge O(1), iterate neighbors O(V). Good for dense graphs. For weighted graphs, store weight instead of 0/1. Symmetric for undirected graphs.

vector<vector<int>> adj(V, vector<int>(V, 0));

adj[1][0] = 1; // undirected

89. Adj List

Adjacency list stores for each vertex a list of adjacent vertices. Space O(V+E), ideal for sparse graphs. Check edge O(degree), iterate neighbors O(degree). Vector of vectors common in C++. Each list entry can store pair{neighbor, weight} for weighted.

adj[0].push_back(3); // 0->3
adj[1].push_back(0); // undirected

90. Add Edge

Add edge in adj list: push_back neighbor. For undirected, add both directions. For weighted, store pair{to, weight}. Time O(1) amortized. Ensure vertex indices valid. For matrix, set mat[u][v] = 1 or weight. Edge list stores all edges as pairs.

void addEdge(vector<vector<int>>& adj, int u, int v) {
    adj[u].push_back(v);
    adj[v].push_back(u); // undirected
}

vector<vector<pair<int,int>>> adjW;

91. Weighted Graph

Weighted graph assigns weight/cost to each edge. Represent in adj list as vector of pairs {neighbor, weight} or struct. In matrix, store weight instead of 1, use INF for no edge. Algorithms: Dijkstra, Bellman-Ford, MST. Weights may represent distance, cost, capacity.

92. Directed Graph

Directed graph edges have direction: u->v does not imply v->u. Represent asymmetric adj list or matrix. In-degree: edges entering vertex, out-degree: edges leaving. DAG is directed acyclic graph, important for topological sort. SCC: strongly connected components.

93. Undirected Graph

Undirected edges bidirectional: u-v means both u->v and v->u. Add edges both ways in adj list. Matrix is symmetric. Degree is total incident edges. Trees are undirected acyclic connected graphs. Connected components found via DFS/BFS traversal.

95. Practice: Count Edges

Count edges in undirected graph from adj list. Each edge counted twice, so sum all list sizes and divide by 2. For directed, sum is exact. Time O(V). Verify by hand for small graph. Handle self-loops carefully if allowed.

int countEdges(vector<vector<int>>& adj) {
    int sum = 0;
    for(auto& lst : adj) sum += lst.size();

    // return sum; // directed

Reveal Answer

96. Trie Concept

Trie or prefix tree stores strings for fast retrieval. Each node represents prefix, edges are characters. Root is empty prefix. Path from root to node spells prefix. Leaf or marked node indicates end of word. Time for insert/search O(L), L = word length.

// Trie for "cat", "car", "dog"
//     root
//    /    \
//   c      d
//   |      |
//   a      o
//  / \     |
// t   r    g*
// *
// * = end of word

97. Trie Node

TrieNode contains array/map of children pointers and boolean flag isEnd. For lowercase letters, array of 26 pointers. unordered_map for unicode or memory efficiency. Space intensive but fast. Each node may store count or other metadata for extensions.

struct TrieNode {
    TrieNode* children[26];
    bool isEnd;
    TrieNode() {
        isEnd = false;
        for(int i = 0; i < 26; i++) 
            children[i] = nullptr;
    }
};

98. Trie Insert

Insert word by traversing from root, creating nodes for missing chars. Mark last node isEnd=true. Time O(L). If word exists, just mark isEnd. No duplicate storage of prefixes. Memory O(ALPHABET_SIZE * N * L) worst case but shared prefixes save space.

void insert(TrieNode* root, string word) {
    TrieNode* curr = root;
    for(char c : word) {
        int idx = c - 'a';
        if(!curr->children[idx])
            curr->children[idx] = new TrieNode();
        curr = curr->children[idx];
    }
    curr->isEnd = true;
}

99. Trie Search

Search traverses trie following word chars. If node null before word ends, not found. At end, check isEnd flag. Time O(L). Distinguishes "cat" in trie vs prefix "ca" that is not word. Faster than hash if many prefixes queried.

bool search(TrieNode* root, string word) {
    TrieNode* curr = root;
    for(char c : word) {
        int idx = c - 'a';
        if(!curr->children[idx]) return false;
        curr = curr->children[idx];
    }
    return curr->isEnd;
}

100. Trie Prefix

startsWith checks if any word has given prefix. Same as search but does not require isEnd=true at end. Used in autocomplete. Return true if path exists. Time O(P) where P=prefix length. Useful for type-ahead features.

bool startsWith(TrieNode* root, string prefix) {
    TrieNode* curr = root;
    for(char c : prefix) {
        int idx = c - 'a';
        if(!curr->children[idx]) return false;
        curr = curr->children[idx];
    }
    return true; // prefix exists
}

101. Trie Delete

Delete word: find path, unmark isEnd. If node has no children and not end of another word, delete it recursively upward. Complex because must not delete prefixes of other words. May use reference counting. If memory not critical, lazy delete by unmarking only.

bool deleteHelper(TrieNode* node, string& word, int depth) {
    if(!node) return false;
    if(depth == word.size()) {
        if(!node->isEnd) return false;
        node->isEnd = false;
        return isEmpty(node); // can delete?
    }
    int idx = word[depth] - 'a';
    if(deleteHelper(node->children[idx], word, depth+1)) {
        delete node->children[idx];
        node->children[idx] = nullptr;
        return !node->isEnd && isEmpty(node);
    }
    return false;
}

103. Practice: Auto Complete

Given prefix, return all words starting with it. Traverse to prefix node, then DFS to collect all words. Store current path string. Time O(P + N) where N is number of nodes in subtrie. Output order depends on DFS order.

void dfs(TrieNode* node, string& prefix, vector<string>& res) {
    if(node->isEnd) res.push_back(prefix);
    for(int i = 0; i < 26; i++) {
        if(node->children[i]) {
            prefix.push_back('a' + i);
            dfs(node->children[i], prefix, res);
            prefix.pop_back();
        }
    }
}
vector<string> autocomplete(TrieNode* root, string pre) {
    TrieNode* curr = root;
    for(char c : pre) {
        int idx = c - 'a';
        if(!curr->children[idx]) return {};
        curr = curr->children[idx];
    }
    vector<string> res;
    dfs(curr, pre, res);
    return res;
}
Reveal Answer

First navigate to the node representing the prefix. If path breaks, return empty. Otherwise, do DFS from that node, appending characters to current prefix string. When isEnd is true, add to results. Backtrack after exploring each child. This collects all words with given prefix.

104. Practice: Word Search

Check if word exists in board using trie for multiple queries. Build trie from dictionary, DFS board while traversing trie simultaneously. Prune paths failing trie. Faster than checking each word separately. Time O(M*N*4^L) reduced by trie pruning.

// Build trie of words
// DFS on board: if cell char in trie child, continue
// Mark visited, backtrack
// If reach trie isEnd node, word found
Reveal Answer

Insert all dictionary words into trie. For each board cell, start DFS if first char matches trie root child. During DFS, move in trie and board simultaneously. If we hit isEnd node, we found a word. Use visited set and backtrack. Trie prunes impossible paths early.

105. Compressed Trie

Compressed trie or radix tree merges chains of single-child nodes into edges with strings. Reduces space significantly. Also called Patricia trie. More complex insert/delete but space O(N) where N is sum of strings. Used in routing, string algorithms. Edges store labels.

// Normal trie: c->a->t
// Compressed: cat (single edge)

106. Hash Concept

Hash table maps keys to values via hash function. Average O(1) insert, delete, lookup. Array of buckets indexed by hash(key). Collisions resolved by chaining or open addressing. Load factor = n/m affects performance. Used everywhere from dictionaries to caches.

107. Hash Function

Hash function maps key to integer bucket index. Should be fast, uniform, deterministic. Poor hash causes clustering and O(n) performance. For strings: polynomial rolling hash. For integers: mod prime. std::hash provides hashers. Cryptographic hashes different purpose: avoid collisions hard.

108. Collision

Collision: two keys hash to same index. Inevitable with pigeonhole principle. Must be resolved. Collisions degrade performance if many. Good hash + low load factor reduce collisions. Birthday paradox: collisions likely even with large table if not uniform.

// key2 -> hash 5 (collision)
// Must handle: chaining or probing

109. Chaining

Chaining: each bucket holds linked list of elements hashing to it. Insert adds to list, search traverses list. Load factor can exceed 1. Simple and handles high load. Worst case O(n) if all keys collide. Used by std::unordered_map. Memory overhead for pointers.

110. Open Addressing

Open addressing: all elements in table itself. On collision, probe for next empty slot: linear, quadratic, double hashing. Deletion tricky: mark tombstone. Performance degrades with high load factor >0.7. Cache friendly versus chaining. Used in Python dicts, Google dense_hash_map.

119. Practice: Longest Seq

122. DSU Find

Find returns representative of set containing element. Naive: follow parent until root O(n). With path compression: flatten tree during find, making future finds faster. Representative of set is root element. Compare find(x)==find(y) to check same set.

        parent[x] = find(parent, parent[x]); // path compression
    return parent[x];

123. DSU Union

Union merges sets containing x and y. Find roots, make one root parent of other. Naive union may create tall trees. Union by rank/size attaches shorter tree under taller to keep depth low. Combined with path compression gives O(α(n)) amortized.

void unionSets(vector<int>& parent, int x, int y) {
    int rx = find(parent, x);
    int ry = find(parent, y);
    if(rx != ry) parent[rx] = ry;
}

124. Path Compression

Path compression flattens tree during find by making every node point directly to root. Performed in recursion return path. Reduces future find time dramatically. Makes trees very flat, depth rarely >5. Critical for near-constant time DSU operations.

125. Union by Rank

    if(rank[rx] < rank[ry]) p[rx] = ry;
    else if(rank[rx] > rank[ry]) p[ry] = rx;

}

Factorial n! = n*(n-1)*...*1, 0!=1. Recursive: n! = n*(n-1)!. Base case n<=1 return 1. Time O(n), space O(n) stack. Iterative better for large n. Overflows int quickly: 13!>int_max. Use long long or check bounds.

long long factorial(int n) {
    if(n <= 1) return 1; // base
    return n * factorial(n-1); // recursive
}
cout << factorial(5); // 120

159. Fibonacci

Fib: F(n)=F(n-1)+F(n-2), F(0)=0, F(1)=1. Naive recursive O(2^n) due to repeated work. Memoization or iterative reduces to O(n). Tree recursion has overlapping subproblems. Classic DP intro. Grows fast, overflows int around n=47.

int fib(int n) {
    if(n <= 1) return n; // base
    return fib(n-1) + fib(n-2); // 2 recursive calls
}
// fib(5) calls fib(3) twice

160. Tail Recursion

Tail recursive: recursive call is last operation. Can be optimized to loop by compiler, eliminating stack growth. Accumulate result in parameter. Factorial tail version passes accumulator. Not all compilers optimize. Still O(n) time but O(1) space if optimized.

long long factTail(int n, long long acc=1) {
    if(n <= 1) return acc; // base
    return factTail(n-1, n*acc); // tail call
}
// Equivalent to loop: acc*=n; n--;

161. Head Recursion

Head recursion: recursive call before processing. Process on unwind path. Cannot be easily tail-optimized. Example: print in reverse. First recurse to base, then print on return. Useful when operation must happen after subcalls complete.

void printRev(int n) {
    if(n == 0) return;
    printRev(n-1); // recurse first
    cout << n << " "; // process after
}
printRev(3); // 1 2 3

162. Tree Recursion

Tree recursion: multiple recursive calls per frame, like fib. Forms call tree. Often exponential time without memo. Natural for tree traversals, combinatorial problems. Analyze with recurrence. Overlapping subproblems indicate DP opportunity. Branch factor affects complexity.

// Tree recursion example
int countPaths(int n) {
    if(n < 0) return 0;
    if(n == 0) return 1;
    return countPaths(n-1) + countPaths(n-2) + countPaths(n-3);
}

163. Backtracking Intro

Backtracking: recursive trial and error. Build solution incrementally, abandon path if invalid, backtrack to try next. Prune search space. Used in N-Queens, Sudoku, permutations. Key: choose, explore, unchoose. Time exponential worst case but pruning helps.

// Backtrack template

    for(choice : options) {
        if(valid(choice)) {
            make(choice); // choose
            backtrack(newState); // explore
            undo(choice); // unchoose
        }
    }
}

164. Practice: Print N

Print 1 to N recursively. Base case n==0 return. Recurse n-1 then print n for ascending, or print n then recurse for descending. Demonstrates head vs tail recursion effect on order. Stack depth O(n).

void printAsc(int n) {
    if(n == 0) return;
    printAsc(n-1);
    cout << n << " "; // after recurse
}

    if(n == 0) return;
    cout << n << " "; // before recurse
    printDesc(n-1);
}
Reveal Answer

For ascending, recurse first to reach 1, then print on unwind 1 to n. For descending, print first then recurse, producing n to 1. Base case stops recursion. This shows execution order difference between processing before vs after recursive call.

165. Practice: Power

Compute x^n recursively. Base: n==0 return 1. Recursive: x*power(x,n-1) O(n). Optimized: fast power x^n = (x^(n/2))^2, O(log n). Handle n<0 by 1/result. Beware overflow. Tail recursive possible with accumulator.

double myPow(double x, int n) {
    if(n == 0) return 1;
    if(n < 0) return 1 / myPow(x, -n);
    double half = myPow(x, n/2);
    if(n % 2 == 0) return half * half;
    else return x * half * half;
}
// O(log n) time
Reveal Answer

Fast exponentiation uses divide-and-conquer: x^n = (x^(n/2))^2 if n even, x*(x^(n/2))^2 if odd. This reduces n by half each call, O(log n) time. Base case n=0 returns 1. Negative n handled by reciprocal. Recursively compute half once to avoid duplicate work.

166. Practice: Reverse Array

Reverse array recursively using two pointers or indices. Swap arr[l],arr[r], recurse l+1,r-1. Base: l>=r stop. Time O(n), space O(n) stack. Iterative two-pointer better. Demonstrates divide-conquer on array. Similar for strings.

void reverseArr(vector<int>& arr, int l, int r) {
    if(l >= r) return; // base
    swap(arr[l], arr[r]);
    reverseArr(arr, l+1, r-1); // recurse
}

Reveal Answer

Use two indices l,r. Base case when they cross. Swap elements at l and r, then recursively reverse subarray l+1 to r-1. Each call handles outer pair, progressing inward. This takes O(n/2) = O(n) calls and swaps. Stack depth O(n).

167. Practice: Palindrome

Check string palindrome recursively. Compare s[l] and s[r]. If equal, recurse l+1,r-1. Base: l>=r return true. If mismatch return false. Time O(n), space O(n). Iterative two-pointer preferred. Demonstrates recursive string processing.

bool isPalRec(const string& s, int l, int r) {
    if(l >= r) return true; // base
    if(s[l] != s[r]) return false;
    return isPalRec(s, l+1, r-1);
}
// Call: isPalRec(s, 0, s.size()-1);

Base case l>=r means all pairs checked, return true. If current ends differ, not palindrome, return false. Otherwise recurse inward. This checks symmetric positions toward center. Recurrence: T(n)=T(n-2)+O(1), solving to O(n). Stack holds O(n) frames worst case.

181. Stack vs Heap

Stack: function calls, local vars, automatic memory, fast allocation, LIFO, limited size ~8MB. Heap: dynamic memory new/delete, manual management, slower, large size, fragmentation. Stack frame destroyed on return. Use heap for large or long-lived data.

void func() {
    int x = 5; // stack
    int* p = new int(10); // heap
    delete p; // must free
} // x auto destroyed

182. Code Segment

Code or text segment stores compiled program instructions. Read-only to prevent modification. Includes functions. Shareable among processes. Size fixed at compile time. CPU fetches instructions from here. Attempts to write cause segfault. Separate from data.

183. Data Segment

Data segment holds global and static variables. Initialized data: globals with value. BSS: uninitialized globals, zeroed at start. Lives entire program. Writable. Separate from stack and heap. Static local vars also here, not on stack.

184. Stack Frame

Stack frame for each function call: parameters, return address, local vars, saved registers. Grows down typically. Frame pointer tracks current frame. On return, frame popped. Deep recursion may overflow stack. LIFO order matches call/return sequence.

upper_bound in sorted range finds first element greater than val. O(log n). lower_bound <= val < upper_bound. Distance between is count of val. Used with equal_range which returns both. Insertion point for strict >.

196. Practice: STL Combo

Combine STL: sort, unique, erase idiom removes duplicates. vector -> sort -> unique -> erase. unique moves duplicates to end, returns iterator to new end. Erase from there. Time O(n log n). Results in sorted unique vector. Common preprocessing step.

// Now v has unique sorted
